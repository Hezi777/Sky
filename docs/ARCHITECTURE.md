# Sky — Architecture

Sky is a single-user personal dashboard. After the folder restructure
(`chore/restructure-folders`, see `MIGRATION.md`) it lives as **three independent
sibling roots**, each a single-stack project that builds on its own.

```
Sky/
├── backend/      Headless Next.js API  ── serves /api/* on http://localhost:3000
├── native/       SwiftUI macOS/iOS app ── primary client, calls backend
└── legacy-web/   Frozen web + Electron  ── reference only
```

## Data flow

```
                       ┌────────────────────────────┐
   native/  ───────────▶  backend/  app/api/*        │
   (SwiftUI)   HTTP     │    └── delegates to lib/*   │──▶ external services
                        │        (GitHub, Notion,     │    (GitHub, Google,
   legacy-web/ ─ ─ ─ ─ ▶│         Spotify, IBKR,      │     Spotify, IBKR,
   (frozen)   (was)     │         Groq, TASE, …)      │     Groq, TASE, Finnhub…)
                        └────────────────────────────┘
                   contract = backend/lib/types.ts
```

- **Only `backend` talks to external services.** Clients call `http://localhost:3000/api/*`.
- The native app additionally hits two **public** APIs directly by design: Open-Meteo
  (weather) and ZenQuotes (daily quote). These need no key and no backend.

## backend/ — API + contract

- Next.js 16 App Router, headless. `app/api/**/route.ts` export `GET`/`POST`/`DELETE`
  handlers; most delegate to `lib/*.ts`.
- `app/page.tsx` / `app/layout.tsx` are minimal stubs so `next build`/`next dev` work
  without a UI. There is intentionally no frontend here.
- `lib/types.ts` is the **single source of truth** for API response shapes. The native
  models and the frozen web types are manual mirrors of it.
- `app/api/` and `lib/` are a unit — never split or relocate one without the other.
- Backend-only tooling under `scripts/`: OAuth token helpers (`get-*-token.mjs`) and the
  IBKR Client Portal Gateway scripts (`scripts/ibkr/`).
- Runs with `npm run dev` → `http://localhost:3000`. This origin is hard-wired into the
  native client (`native/Sky/Networking/APIClient.swift` default base URL).

## native/ — primary client

- Swift 6 / SwiftUI, generated by XcodeGen from `native/project.yml` (canonical).
- Builds standalone from within `native/`: `xcodegen generate` + `./build-mac.sh`.
  No dependency on root or backend scripts.
- `native/Sky/Models/*.swift` mirror `backend/lib/types.ts` by hand. A response-shape
  change is a synchronized edit in `backend/lib` + the native models.
- Has its own copies of shared artwork in `native/Sky/Assets.xcassets/` and its own
  adaptive icon source `native/Sky/AppIcon.icon/` — these are platform packaging inputs,
  intentionally duplicated with `legacy-web/public/`.

## legacy-web/ — frozen

- The previous web dashboard (`app/page.tsx`, `components/`, `hooks/`) and the Electron
  shell that packaged it (`electron/`, `electron-builder.yml`, `public/`, `assets/dmg`,
  the desktop CI workflow).
- Frozen reference: **never edited, linted, or built.** Its `lib/` is a verbatim snapshot
  copy of `backend/lib/` taken at split time, kept only so the archived imports point at
  real files. Resolution/compilation is not guaranteed and not maintained.
- Includes the dead files that predated the split (e.g. `components/widgets/github-repos.tsx`,
  `greeting-card.tsx`, `glass-card.tsx`, `memoji-picker.tsx`, `layout/header.tsx`,
  `layout/sidebar.tsx`) — moved here rather than deleted.

## Shared / duplicated by design

- Cloud + sky artwork exists in both `legacy-web/public/assets/{cloud,sky}/` and
  `native/Sky/Assets.xcassets/`. The adaptive icon source exists in both
  `legacy-web/public/Mac Icon.icon/` and `native/Sky/AppIcon.icon/`. These are
  platform-specific packaging inputs; each surface owns its copy. Keep them in sync by hand.
- `backend/lib/` is the canonical integration code; `legacy-web/lib/` is a frozen copy.

## Constraints

- No database, no auth, single page — live-fetched personal app.
- Secrets are server-side only (`backend/.env.local`); never shipped to clients. The
  native `SKY_API_TOKEN` is a client header convention only — no backend middleware
  validates it today.

> `legacy-web/` was removed from the working tree. It remains in git history and is recoverable with `git checkout <commit-before-removal> -- legacy-web`.
